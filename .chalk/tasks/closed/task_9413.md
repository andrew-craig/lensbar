PLAN.md §6 Phase 0 step 6. Extension counts source-stream start/stop and exposes it as a custom property. Check whether the app receives property-change notifications or needs ~1 s polling (risk table fallback).

## Result (2026-11-17) — PASS: notifications work, polling not needed
Extension exposes custom device property `4cc_lbcc_glob_0000` (String, running source-stream
client count) and calls `device.notifyPropertiesChanged` on every source start/stop.
App side (`spike/prop/main.swift`): CMIO selector 'lbcc', global scope, element main;
`CMIOObjectGetPropertyData` returns a CFString; `CMIOObjectAddPropertyListenerBlock` on the
device fires ~40 ms after the extension's start/stop (11:39:06.818 start → listener 11:39:06.861;
11:39:10.472 stop → 11:39:10.515). 1 s polling ran alongside and always agreed.
- Works from an unsandboxed process with no camera TCC and no entitlements (the Claude Bash tool).
- Write path works too: `CMIOObjectSetPropertyData` with a CFString on 'lbfm' reaches
  `setDeviceProperties` (used for task_c735).
- The CMIO device object ID can change when devices come and go (40 → 89 → 46 → 89 seen);
  re-resolve by UID on kCMIOHardwarePropertyDevices changes and re-add listeners.
- Zoom opens/closes the source many times per call, so client count flaps; keep the grace period.
Recommendation: listener-driven, with a slow poll (e.g. 5 s) only as a safety net.

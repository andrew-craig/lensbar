PLAN.md §6 Phase 0 step 2. Xcode Camera Extension template in a scratch project, signed with the dev team, installed from /Applications, approved in Login Items & Extensions → Camera Extensions. Confirms activation works from a signed build (exit criterion).

## Result (2026-11-17)
`spike/camera-extension/` — XcodeGen spec (`xcodegen generate`) for LensBarSpike.app +
com.andrewcraig.LensBarSpike.Camera.systemextension (template-equivalent CMIOExtension with a
source stream, a sink stream that forwards to the source, and a moving placeholder; one
1280x720 NV12 format at exactly 25 fps). Fixed UIDs: device 6A1B6C2E-…-5A60, source …5A61, sink …5A62.

Build: `xcodebuild -project spike/camera-extension/LensBarSpike.xcodeproj -scheme LensBarSpike
-configuration Debug -derivedDataPath build/spike-dd -allowProvisioningUpdates
-allowProvisioningDeviceRegistration build`, then `ditto` to /Applications and
`open /Applications/LensBarSpike.app --args --activate`.

Findings:
- Automatic signing with Apple Development (team B8A6HLKG3J) works for the restricted
  system-extension.install entitlement; required registering this Mac (ac-mba) in the account.
- Mach service `B8A6HLKG3J.com.andrewcraig.LensBarSpike.Camera` under app group
  `$(TeamIdentifierPrefix)com.andrewcraig.LensBarSpike` is accepted.
- XcodeGen `embed: true` on a system-extension dependency puts it in Contents/Library/SystemExtensions.
- Approval UX: the first toggle attempt did not register; it took the (i) → toggle → password
  path in Login Items & Extensions. State went `activated waiting for user` → `activated enabled`.
- Harness against "LensBarSpike Camera": placeholder source stream measured 25.00 fps, ~40 ms gaps.
- Not yet tested: activation from a Developer ID / notarized build (Phase 5 risk, not this spike).
